# 初一班主任管理系统 · 总体设计

> 定位：一个**属于你自己的班主任工作台** —— 数据私有、三端适配（iPad / 笔记本 / 手机）、
> 以学生档案为中心的数据一体化系统，覆盖班主任日常 + 语文任课教师的成绩管理。
> 技术栈：**响应式 Web 前端 + 本地数据层（IndexedDB）**。
>
> 📌 **开源版本说明**：本目录是项目的设计文档存档。早期原型曾采用 Supabase（PostgreSQL +
> Auth + Storage + RLS）作为后端，开源版本（本仓库根目录的 Next.js 应用）的数据层已改为纯本地实现
> （浏览器 IndexedDB + 本机账号），无需任何云服务；`supabase/schema.sql` 保留下来仅作为
> **数据模型参考**（表结构、视图与函数的语义与本地引擎 `lib/local-core.ts` 一致）。

## 一、设计原则（调研自市面产品的成败教训）

1. **录入效率第一**：班主任时间碎片化，所有高频录入必须是"默认值 + 点选 + 批量 + 粘贴"。
   凡是需要打字超过 5 秒的操作，都要有模板或快捷方式。（教训来源：班主任用系统又退回 Excel）
2. **一个工作台贯穿学期**：打开系统默认进入"今日看板"，所有日常操作从看板一键进入。
3. **数据一体化**：学生档案是中心，考勤/作业/事件/谈话/成绩/联系全部挂接在学生的成长时间线上，
   期末评语、学期报告由平时记录自动聚合 —— 这是市面多个孤立 App 做不到的。
4. **工具化而非制度化的激励**：借鉴"随机点名、小组活动"等课堂工具，但不做积分排名
   （避免公开排名焦虑，也避免班主任维护负担）。
5. **打印与导出是刚需**：学校要求交纸质材料（成绩条、操行评定、考勤汇总、值日表、签到表），
   提供统一的"打印中心"，A4 排版、手机号脱敏。
6. **隐私可控**：只录必要信息（不录身份证号），Supabase 项目私有 + RLS 行级安全，
   每周一键备份到本地。

## 四、技术方案

| 层 | 选型 | 说明 |
|---|---|---|
| 数据库 | Supabase PostgreSQL 15+ | 免费层 500MB，一个班数据绰绰有余 |
| 认证 | Supabase Auth（邮箱+密码） | 单用户；创建账号后关闭公开注册 |
| 文件 | Supabase Storage（photos 桶，私有） | 学生照片、活动照片 |
| 权限 | RLS 行级安全 | 所有表只允许 owner 访问（见 schema.sql） |
| 前端 | Next.js（或 Vue/React）+ supabase-js + Tailwind | 响应式：<640 手机 / 640-1024 iPad / >1024 桌面 |
| 部署 | Vercel / Netlify | 免费层即可，环境变量指向 Supabase 项目 |
| 备份 | 内置"一键导出 JSON + 每周提醒" | 弥补免费层无自动备份 |

**前端页面清单（v1，约 22 个页面）**：登录、今日看板、学生列表/详情（含成长时间线）、
班级设置、**座位编辑（拖拽）**、**导入中心**、考勤（打卡/请假/汇总）、值日、作业、
课堂工具、事件台账、谈话、重点关注、考试管理、成绩录入/分析、学习小组、家校联系、
家长会、通知、班委、班会、活动、荣誉墙、评语、学期报告、归档、打印中心、**安全中心**、设置。

## 五、部署步骤（Supabase）

1. 注册 [supabase.com](https://supabase.com)，创建项目。**区域注意**：海外节点涉及学生数据出境合规（PIPL），
   方案权衡见 `docs/04-数据与使用安全设计.md` §4。
2. 打开 **SQL Editor**，执行 `supabase/schema.sql`（建表、索引、RLS、视图、函数）。
3. **Authentication → Providers → Email** 开启邮箱登录；先创建你自己的账号，
   然后在 **Authentication → Settings** 里**关闭公开注册**（Allow new users 关掉），保证只有你能注册。
4. **账号安全**（Authentication）：开启 **MFA（TOTP 二步验证）**（强烈建议）；设置强密码（≥10 位混合字符）；
   Session 过期时间建议 7 天。
5. **Storage → New bucket** 创建 `photos`，选择 private；复制 `supabase/storage-policies.sql` 中的策略执行。
6. 前端项目配置环境变量：`NEXT_PUBLIC_SUPABASE_URL`、`NEXT_PUBLIC_SUPABASE_ANON_KEY`（**service_role key 永不进前端**）。
7. 部署到 Vercel/Netlify 后，在手机/iPad 浏览器"添加到主屏幕"，即可当 App 用。
8. **上线安全自查**：① 公开注册已关闭 ② MFA 已绑定 ③ 未登录访问 API 被拒（RLS）④ 每周备份已开启。

## 六、数据模型总览（详见 02-数据库设计.md）

```
profiles (用户) 1──1 app_settings
school_classes (班级) 1──N students
students 1──N  attendance_records / leave_requests / homework_records /
               behavior_events / talks / home_school_contacts /
               grade_records / term_reports / class_leaders
school_classes 1──N  seats / duty_groups / duty_records / attendance_sessions /
                      exams / parent_meetings / class_meetings / activities /
                      honors / todos / notice_drafts
exams 1──N exam_subjects 1──N grade_records
```

所有业务表带 `class_id`，RLS 统一走 `is_class_owner(class_id)` 校验。

## 七、v2 路线图（按优先级）

1. **量化积分**（规则库 + 排行榜 + 光荣榜 + 兑换）—— 需要时开启，默认关闭
2. **语文教学专项**：背诵默写过关管理 / 作文批改记录 / 名著阅读打卡（任教班模块）
3. **AI 评语生成**（接入大模型 API，基于记录生成初稿）
4. **家长周报**：每周自动汇总学生表现，导出图文卡片发家长群
5. **课堂大屏模式**：教室一体机展示随机点名/活动 PK（班级优化大师的玩法）
6. **多教师协作**：搭班老师只读权限
