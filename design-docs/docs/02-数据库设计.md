# 班主任管理系统 · 数据库设计（Supabase / PostgreSQL）

> 可执行版本见 `supabase/schema.sql`，本文解释设计决策。

---

## 1. 设计总则

1. **单用户优先**：所有业务表通过 `school_classes.owner_id = auth.uid()` 归属，
   其余表统一携带 `class_id`，RLS 策略通过 `is_class_owner(class_id)` 校验，扩展多用户时只需改这一处。
2. **class_id 冗余到所有业务表**：换索引与 RLS 的简单性，避免多表 JOIN 才能鉴权（小数据量可接受）。
3. **枚举用 text + CHECK**：不用 PG enum 类型，避免 `ALTER TYPE` 的迁移痛苦；枚举校验在应用层 + CHECK 双保险。
4. **软删除**：业务表带 `deleted_at`，删除=置时间戳；列表查询 `where deleted_at is null`。
5. **时间一律 timestamptz**，日期用 date。
6. **统计不落库**：均分/优秀率/排名等全部由视图或应用层实时计算，避免数据不一致。

## 3. RLS 设计

核心函数（security definer，避免重复 JOIN）：

```sql
create or replace function is_class_owner(cid uuid)
returns boolean language sql security definer stable as $$
  select exists (
    select 1 from school_classes c
    where c.id = cid and c.owner_id = auth.uid()
  );
$$;
```

每个业务表的策略模式（以 students 为例）：

```sql
alter table students enable row level security;
create policy "students_select" on students
  for select using (is_class_owner(class_id));
create policy "students_insert" on students
  for insert with check (is_class_owner(class_id));
create policy "students_update" on students
  for update using (is_class_owner(class_id)) with check (is_class_owner(class_id));
create policy "students_delete" on students
  for delete using (is_class_owner(class_id));
```

profiles / app_settings / comment_library / backup_logs / import_logs / audit_logs：`user_id = auth.uid()`。
school_classes：`owner_id = auth.uid()`。
exams 等经 class_id 间接鉴权（`is_class_owner(class_id)`）。

> 注：启用 RLS 后，`delete` 策略若不需要物理删除可只给软删除接口（应用层 UPDATE deleted_at），
> schema.sql 中仍提供 delete 策略以便管理端清理。

| `v_growth_timeline` | 每生聚合时间线（考勤/作业/事件/谈话/联系/荣誉） |

## 5. 函数（存储过程）

| 函数 | 作用 |
|---|---|
| `set_updated_at()` | updated_at 触发器 |
| `is_class_owner(uuid)` | RLS 鉴权 |
| `fn_rotate_seats(p_class uuid, p_steps int)` | 座位轮换（行列位移）并写 seat_history |
| `fn_generate_seats_by_rules(p_class uuid, 规则 jsonb)` | 规则排座（身高/男女/成绩/锁定） |
| `fn_rotate_duty(p_class uuid)` | 值日组周轮换 |
| `fn_approve_leave(p_leave uuid)` | 批准请假 → 生成考勤记录 |
| `fn_finish_leave(p_leave uuid, p_return date)` | 销假 |
| `fn_generate_comment(p_student uuid, p_term text)` | 聚合记录生成评语草稿（模板句） |
| `fn_export_all(p_user uuid)` | 全量导出 JSON（备份） |

> `fn_generate_comment` 的草稿规则（v1 模板化，v2 可接 LLM）：
> 优点句 = 表扬事件类别统计 + 荣誉 + 成绩优秀科目；
> 进步句 = 与上次考试对比进步科目 + 出勤改善；
> 期望句 = 未交作业次数/违纪类别 + 偏科科目；
> 鼓励句 = 评语库随机/按类别选取。

## 6. 数据量预估与索引策略

- 单班 50 生 × 3 年 ≈ 150 条学生记录；考勤 50×5 节点×200 天 ≈ 5 万条/班/年
- 成绩 50 生 × 7 科 × 10 场 ≈ 3500 条/班/年
- 全部数据量 < 100MB，免费层 500MB 无压力
- 索引已覆盖高频查询：`(class_id, date)`、`(student_id, date)`、`(class_id, student_no)` 唯一等
- 部分唯一索引处理"每日总考勤"与"节点考勤"两套唯一性（见 2.3）
