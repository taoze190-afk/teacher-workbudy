# 数据安全与使用安全设计

> 配套：`supabase/schema.sql`（audit_logs 表）、`docs/01-功能规格说明书.md` H5/H6、`docs/02-数据库设计.md`。
> 核心原则：**威胁主要来自"身边的眼睛"，而不是"远方的黑客"** —— 班主任的手机/电脑常被学生、家长碰到，
> 防偷看、防误删、防外泄，比防网络入侵更优先。

---

## 1. 威胁模型

| 威胁 | 来源 | 等级 | 对策 |
|---|---|---|---|
| 偷看（学生凑近屏幕） | 高频 | 🔴 高 | 应用锁、一键隐藏、敏感页模糊 |
| 截图外泄（转家长群/朋友圈） | 中频 | 🔴 高 | 水印溯源、脱敏默认 |
| 手机/电脑丢失 | 低频 | 🔴 高 | 退出所有设备、MFA、本地备份 |
| 家长/同事借用设备 | 中频 | 🟡 中 | PIN、敏感页二次验证 |
| 账号被盗/网络入侵 | 低频 | 🟡 中 | 强密码、MFA、RLS、service_role 保护 |
| 误操作（删错/覆盖） | 高频 | 🟡 中 | 二次确认、回收站、覆盖前备份 |
| 数据出境合规 | 长期 | 🟡 中 | 区域选择、数据最小化、告知家长（§4） |
| Supabase 侧泄露/服务中断 | 极低 | 🟢 低 | 定期本地加密备份 + pg_dump |

## 2. 数据安全机制

### 2.1 传输与存储
- 全链路 HTTPS（Supabase API + Vercel/Netlify 前端默认强制）
- 数据库磁盘加密（Supabase 托管默认）；文件存私有 `photos` 桶（策略已实现）
- **service_role key 永不进前端**：只配 anon key（已被 RLS 限制到你的数据），service_role 仅服务端/Edge Function 可用

### 2.2 访问控制（RLS）
- 全部业务表统一 `is_class_owner(class_id)` 策略（security definer）——已实现
- **audit_logs 只增不改**：仅有 select/insert 策略，无 update/delete —— 审计记录不可篡改
- 验收标准：未登录查询返回空；伪造 class_id 越权读写被拒
- 应用层二次校验：导出/删除前在服务端校验归属（不依赖 UI 判断）

### 2.3 敏感字段策略
| 字段 | 存储 | 展示 |
|---|---|---|
| 身份证号 | **不录入** | — |
| 手机号 | 明文（必要） | 列表打码 `138****1234`，详情点击展开 |
| 住址 | 明文（必要） | 仅详情页 |
| 健康备注 | 明文 | 仅详情页 |
| 重点关注原因 | 明文 | 台账页姓名模糊化，导出默认排除 |
| 心理/敏感事件 | 明文 | 事件列表默认不展开详情 |

**决策说明**：不做字段级加密（pgcrypto）——单用户场景下 RLS + 打码 + 水印已覆盖主要风险；
字段加密会牺牲搜索/筛选且恢复复杂。将来若多人协作再评估。

### 2.4 备份与恢复
| 层级 | 方式 | 频率 |
|---|---|---|
| 日常 | 每周备份提醒 + 一键全量导出 JSON（`fn_export_all`） | 每周 |
| 加密 | **加密备份**：导出时设密码 → 前端 Web Crypto **AES-GCM** 加密 → `.dshbak` 文件（密码不落盘） | 每周 |
| 兜底 | `pg_dump`（数据量小时最可靠） | 每月 |

```bash
# pg_dump 示例（Supabase 项目设置 → 数据库连接串）
pg_dump --dbname=postgresql://postgres:[PASSWORD]@db.[PROJECT_REF].supabase.co:5432/postgres -F c -f banzhuren-202509.dump
# 恢复
pg_restore -d postgresql://... banzhuren-202509.dump
```

- 恢复：导入 `.dshbak` → 输密码解密 → 预览 → 恢复（v1.5）
- 保留策略：本地保留最近 4 份（周导出 + 月 dump）

### 2.5 数据生命周期
- 软删除 + 回收站 30 天（误删可救）
- 回收站"清空" = 物理删除（二次确认 + 审计记录）
- 转学生：档案保留（历史记录有价值），标记离班
- 毕业：归档 + 成长手册导出；合规建议毕业后 1 年整班清除（见 §4）

### 2.6 审计日志（audit_logs，只追加）
记录事件：
| action | 触发场景 |
|---|---|
| `login` / `login_failed` | 登录成功/失败（含 IP，自查异地登录） |
| `view_sensitive` | 查看重点关注台账 / 成绩排名 / 完整档案 |
| `export` | 导出备份 / Excel / 报告（含脱敏状态） |
| `import` | 导入（明细见 import_logs） |
| `print` | 打印敏感表格 |
| `delete` | 清空回收站 / 批量删除 |
| `restore` | 恢复备份 |
| `lock_hide` | 触发一键隐藏（应急留痕） |

安全中心可查"最近 50 条操作记录"；日志表无 update/delete 权限（防篡改）。

## 3. 用户使用安全机制

### 3.1 账号认证
| 项 | 设置 |
|---|---|
| 登录方式 | Supabase Auth 邮箱+密码（**关闭公开注册**，部署步骤已含） |
| 密码策略 | ≥10 位，含大小写+数字+符号 |
| **MFA** | **TOTP 二步验证，强烈建议开启**（Supabase Auth 原生支持） |
| 会话过期 | 建议 7 天；refresh token rotation 开启（Supabase 默认） |
| 设备管理 | 安全中心查看最近登录 + 一键"退出所有设备" |

### 3.2 应用锁（PIN）
- 登录后设置 4-6 位 PIN，**存设备本地（localStorage），不进数据库**（设备级安全）
- 空闲锁定：5 / 15 / 30 分钟（默认 15 分钟）；锁定期内重新打开需 PIN
- 多设备独立设置（手机 / iPad / 电脑互不影响）

### 3.3 敏感页二次验证
进入以下页面需 PIN（或登录密码）：
- 重点关注学生台账（红黄名单 + 原因）
- 学生心理/敏感事件详情
- 成绩排名视图（图表 + 表格）
- 完整手机号展开

### 3.4 一键隐藏（伪装页）
- 手机端悬浮"隐藏"按钮（**长按触发**防误触）
- 触发后瞬间切到伪装页（空白/天气样式），敏感组件卸载不留痕迹
- 恢复需 PIN；触发记入审计日志（`lock_hide`）

### 3.5 水印（防截图外泄）
- 敏感页面叠加半透明斜纹水印：`张老师 · 2025-09-01 · 内部资料`
- 导出物（PDF/PNG：成绩条、分析报告、座位图、成长手册）页眉加水印（可选开关）
- 作用：截图/拍照外泄后可溯源（谁 + 什么时间）

### 3.6 误操作保护
- 高危操作统一二次确认（红字警示）：批量删除、清空回收站、覆盖导入、整班归档
- 覆盖导入前自动备份被覆盖数据（记入 backup_logs）
- 所有删除走回收站（30 天内可恢复）

### 3.7 失窃与应急（速查卡）
1. 设备丢失 → 用另一台设备登录 → 安全中心 → **退出所有设备**
2. 重置密码 + 确认 MFA 绑定（MFA 设备也丢则用 Supabase 控制台 Recovery Codes）
3. 检查最近备份（本地 `.dshbak` / pg_dump）是否完好
4. 怀疑账号泄露 → Supabase 控制台 → Authentication → Users → 撤销会话

## 4. 合规（PIPL 与未成年人数据）—— 重要提醒

1. **法律定位**：学生手机号、住址、健康信息、行为记录属个人信息；未成年人信息属**敏感个人信息**。
   《个人信息保护法》要求：最小必要、目的明确、告知同意、保存期限。
2. **个人工具场景的合规姿态**：
   - 数据最小化：只录班级管理必要字段（已执行：不录身份证号）
   - **告知家长**（开学文案，设置页提供"复制"按钮，可直接发家长群）：
     > 各位家长：班级日常管理需要记录孩子的基本信息、联系方式及在校表现。
     > 该信息仅由班主任本人使用，保存在个人私有账号中，不对外提供、不用于任何商业用途，
     > 学期结束后按学校规定归档或删除。如有疑问可随时与班主任沟通。
   - 保存期限：学生在读期间 + 毕业后 1 年，之后清除或整班导出后删除
3. **数据出境（Supabase 区域）**：Supabase 无中国大陆节点（可选新加坡/东京等）。
   严格而言，个人信息出境需单独同意或安全评估。缓解方案（按推荐度）：
   - **推荐 A（务实）**：新加坡节点 + 告知家长（文案如上）+ 数据最小化 —— 个人班主任场景的可行做法
   - **推荐 B（最稳）**：国内云 PostgreSQL（腾讯云/阿里云 RDS，数据不出境）+ 自建简单认证 —— 合规但开发量增加
   - **推荐 C（本地）**：Docker 自托管 Supabase（NAS/家庭服务器）—— 数据完全本地，免费，需自己维护
   - 不推荐：第三方"Supabase 中国代理"服务
4. **与学校平台的关系**：本系统定位"个人工作辅助"，不替代学校统一平台，不与学籍系统冲突。

## 6. 验收测试

1. 未登录访问 API → 全部被拒（RLS 生效）
2. 登录后修改 `audit_logs` → 被拒（只追加）
3. 空闲 15 分钟 → 锁定；进入重点关注页 → 要求 PIN
4. 一键隐藏 → 页面瞬间切换，返回需 PIN
5. 导出 PDF → 含水印；导出 Excel 默认脱敏
6. 清空回收站 → 二次确认 + 审计记录
7. 加密备份 → 无密码无法打开 `.dshbak`
